OTP / SMS Verification Testing Checklist

Vendor-neutral QA checklist for engineers who ship SMS one-time-passcode flows. Use it in staging before release, when mocks are not enough.

0 / 0 checks complete

Why this exists

SMS verification breaks in small ways: codes arrive late, expire early, get rate-limited, or fail on certain country formats. Most of these bugs only show up with real inbound SMS, not mocks.

Failure modeWhat users see
Slow deliveryCode never appears before they abandon
Early expiry“Invalid or expired code” after a resend
Rate limitsTemporary blocks after spam-clicking resend
Format mismatchCountry picker and dialing code disagree
Log leaksOTP strings land in analytics or error trackers

How to use it

  1. Work through the checklist on a staging build that can send real SMS.
  2. Record p50 / p95 delivery time for at least one country.
  3. Fail the release if any security or privacy item is unchecked.
  4. Prefer passkeys or authenticator apps for high-risk actions once the SMS path is proven.

          Testing with real inbound SMS

          For end-to-end tests across countries, temporary inbound numbers help you exercise live carrier routes without tying QA to personal SIMs.

          See the QA checklist write-up and the SMS verification API guide. Only test apps you own or are authorized to test.

          Pass criteria

          Treat the release as not ready if any security or privacy box is unchecked, if p95 delivery exceeds your product SLO, or if resend does not invalidate the previous code.
